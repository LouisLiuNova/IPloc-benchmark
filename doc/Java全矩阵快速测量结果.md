# Java 全矩阵快速测量结果

> 本文保留对应 Java 评估轮次的范围与结果。Rust/JNI 九策略现已实现，当前验证与跨候选数据见 [九策略配对快速报告](Rust九策略配对快速测量结果.md)。

日期：2026-11-04。**128/128 个测量组合全部完成，资源保护未触发。** 用户明确选择先完成快速矩阵；正式独立 fork 长测留到后续，原正式运行已停止，未作为完整成绩使用。

本轮为探索性测量：JMH forks=0，每个数据/索引分组只加载一次快照，1×1 秒预热、1×1 秒测量，各场景共享 JIT/GC 历史。JMH 对 non-forked 模式有调试用途警告，编译提示和 profiler 行为可能与正式 fork 不同；以下绝对值不能直接与正式长测混比，也不能据此宣称生产 SLO 或稳定的最优配置。

- CPU：Intel(R) Core(TM) 5 220H，16 个逻辑 CPU；WSL2，约 15.37 GiB 内存。
- JDK 11.0.32.1、Maven 3.9.11、Parquet Java 1.17.1、JMH 1.37；评估 JVM 最大堆 10 GiB。
- 测量源码提交：`36899596d9ae66e823bee2782df92236874bedba`；JAR SHA-256：`654f6ae2c3b044b0954f806eafcbc143e76ec62b5f36e6641e44b4ddb219e04b`。

- JDK 11 构建、13 项契约测试通过；基础二分及前缀目录分别通过真实全量 5,171 个独立样本的行号与八字段校验。评估运行器共 9 项测试通过。

八字段路径明显低于仅行号查询，应以真实业务需要的结果路径做选择。在本轮观测中，B=1,024/4,096 的多线程载荷路径值得优先正式复测；B=65,536 没有显示出一致优势。不同路径的消费逻辑不同，差值不能直接当作单独步骤的精确耗时。

16 位前缀目录在本轮全部九个行号组合中均显示更高吞吐，但仅验证了整数到行号路径，不据此推断载荷或 JNI 的端到端收益；默认算法没有切换。
