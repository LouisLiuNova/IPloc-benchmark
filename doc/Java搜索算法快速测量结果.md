# Java 搜索算法快速测量结果

> 本文保留对应 Java 评估轮次的范围与结果。Rust/JNI 九策略现已实现，当前验证与跨候选数据见 [九策略配对快速报告](Rust九策略配对快速测量结果.md)。

日期：2026-11-04。用户指定的不同位数／两级前缀、4/8 路交错二分、Eytzinger 均已实现，含基础与组合对照共 **9 个策略**。本轮 **486/486 个测量组合通过**，没有缺项、额外项或重复项，资源保护未触发。

## 方法与核验

- 测量源码提交：`db5810f504687adde18a109a7bc546986137997e`；JAR SHA-256：`c3315bc111ef16630448e47a392d8e3092b705141226f9d05a14de38cdc88832`。
- 真实数据：32,307,681 行、324 个 Row Group；SHA-256 `53defbfb94785be2fa064d42cf85ab26de8a8fa88bf9cd1d5c2c587a77f1b7da`。
- CPU：Intel(R) Core(TM) 5 220H，16 个逻辑 CPU；WSL2、约 15.37 GiB 内存；JDK 11.0.32.1，JMH 1.37，最大堆 10 GiB。
- JDK 11 构建、59 项契约/边界测试及 10 项评估运行器测试通过。9 个策略分别通过同一份独立 PyArrow oracle 的 5,171 个样本行号及八字段比对。
- 矩阵为 9 策略 × B=1,024/4,096/65,536 × C=1/4/8 × 行号/UTF-8/字符串 × thrpt/sample；Q=1,000,000 输入池由线程分摊，查询、消费及数据版本一致。
- 全量数据仅加载一次，策略视图共享不可变边界及载荷，逐策略构建/关闭索引。构建与输入生成在计时之外，查询含实际结果消费；执行顺序由独立固定种子 20261104 打乱并记录。

**本轮为探索性快速测量：JMH forks=0，1×1 秒预热及 1×1 秒测量，共享 JIT/GC 历史。** JMH 对 non-forked 模式有调试用途警告；编译提示、类型画像及 profiler 行为可能与正式 fork 不同。以下数字不用于生产 SLO，不证明稳定最优配置，也不与前一轮 128 项结果跨版本直接混比。

本轮性能只比较真实数据上的合法 IPv4（100% 命中）；合成空洞数据用于全策略算术正确性测试。新增算法没有另行重复旧版合成命中率性能矩阵。

## 本轮观察

- 在 B=4,096、C=8 下，prefix20 的行号约 63.84 百万 IP/s，UTF-8 约 3.91 百万 IP/s；基础二分分别约 13.87 和 2.95。行号路径的提升幅度不能直接套用到八字段路径。
- 纯 4/8 路交错在该配置的行号吞吐相近（约 20.77 / 20.55 百万 IP/s），本轮没有显示路数越多就越快。
- 字符串路径的 prefix16-interleaved8 与 prefix16-24 在该配置分别约 3.01 / 2.97 百万 IP/s，差距很小，应一起正式复测，不据此判定稳定胜负。
- Eytzinger 在该配置的行号高于基础二分，但 UTF-8 低于基础二分，未显示全面优势；额外索引约 246.5 MiB，本机资源保护未触发。

## 延迟与结论边界

完整 P50/P95/P99、误差、样本数和 allocation/GC 指标保存在指标摘要及原始 JMH 记录中。短测批次样本多数不足 10,000，不将 P99 当作稳定尾延迟证据；数量达标也不替代独立长测。
