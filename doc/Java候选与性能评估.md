# Java 候选与性能评估

日期：2026-11-04。范围：独立分支开发、分步提交，经 PR 合并至 main；main 中并列维护候选目录。Java 已实现；Rust/JNI 仅预留工程，不生成成绩。

后续新增三类 Java 搜索算法及完整对照见[算法说明](./Java搜索算法候选.md)和[486 项结果报告](./Java搜索算法快速测量结果.md)。本文保留首轮 128 项评估的方法与范围。

## 实现与依据

复用 Apache Parquet Java 1.17.1 的本地文件、列投影和 RecordMaterializer 接口，自研范围限于业务校验、连续边界数组、分块载荷和批量契约；不实现解码器、通用 SQL 或区间树。官方源码及 Java 11 构建约束见 [Parquet Java](https://github.com/apache/parquet-java/tree/apache-parquet-1.17.1)。微基准采用 [OpenJDK JMH](https://github.com/openjdk/jmh)，不自建吞吐计时循环。

边界为两个连续 int 数组，按无符号比较执行前驱二分。载荷每块最多 65,536 行，逐字段保存 UTF-8、offsets 和 validity；不长期保存逐行 String，不增加自定义字典压缩。16 位目录仅缩小搜索范围并保留目录前一个候选，防止跨前缀长区间漏查；属于单独实验。

## 本轮测量决策

用户在观察每 fork 约 26 秒的加载成本后，明确选择先完成全矩阵快速测量，正式长测留到后续。快速模式保持全部 128 个测量组合，以真实数据、合成数据和前缀目录三个串行进程分组；每进程只加载一套快照，采用 JMH forks=0、1×1 秒预热、1×1 秒测量。各场景共享 JIT/GC 历史，没有独立 fork 误差估计，仅支持探索性比较。JMH 对 non-forked 模式有调试用途警告，编译提示和 profiler 行为可能与正式 fork 不同。完整快速矩阵已完成，见[实测结果](./Java全矩阵快速测量结果.md)。原正式运行已按该决策停止，保留日志但不作为完整正式成绩。

## 性能矩阵

每工作单元输入池 Q=1,000,000，固定种子 20261104，线程按索引分摊池；每次 JMH invocation 精确处理 B 项，循环消费各自输入分片，跨分片尾部时分两次 lookup，结果仍保持完整批次。数据加载、输入生成和线程缓冲初始化在测量之外；加载时间由每 fork 控制台单独记录。按批次测延迟，不将整百万输入池的时间写成批次延迟。

| 场景 | 数据 | 批次 B | 线程 C | 测量路径 |
|---|---|---|---|---|
| 主矩阵 | 真实全量 32,307,681 行 | 1,024 / 4,096 / 65,536 | 1 / 4 / 8 | 行号、八字段 UTF-8、八字段字符串 |
| 补测 | 真实全量 | 1 / 256 / 1,000,000 | 1 | 同上 |
| 空洞 | 合成 10,000,000 行 | 4,096 | 1 / 4 | 同上，命中率 0% / 50% / 90% |
| 前缀目录 | 真实全量 | 1,024 / 4,096 / 65,536 | 1 / 4 / 8 | 仅行号，显式启用前缀目录 |
| 字符串入口 | 真实全量 | 4,096 | 1 | 严格解析、状态与 UTF-8 载荷 |

所有场景分别运行 thrpt 和 sample，正式配置为 3 forks、5×1 秒预热、10×1 秒测量。短预检为 1 fork、1×1 秒预热与测量，不能替代正式矩阵。加载真实快照每次约几十秒，完整矩阵预计耗时数小时。吞吐以 JMH ops/s × B 换算 IP/s，sample 指标为秒/批次；并发吞吐为总量，不再乘线程数。

行号逐项交给 Blackhole；UTF-8 路径消费 validity、offsets 和每个字节；字符串路径创建并逐字段消费 String。不同路径的消费成本不同，性能差值不应直接解释为某个单独步骤的精确耗时。字符串入口包括便利方法额外分配，单独报告。合成数据使用固定 stride=256、width=128，载荷内容与真实数据不同，不能视为生产负载。

## 必要校验与资源保护

契约覆盖基础二分与前缀目录的端点、空洞、无符号地址、重复项、偏移、字段、空值、关闭和坏数据。独立 PyArrow oracle 流式读取投影列，以终点后继与起点检查得到预期行号，不调用 Java 查找；抽样覆盖固定随机地址和每 Row Group 边界。真实全量结果与 5,171 个样本的行号及八字段比对。

资源占用仅用于防止本机耗尽，不单独执行 100 次加载/释放、30 分钟稳定性或泄漏专项。评估父 JVM 最大堆 256 MiB，fork 最大堆 10 GiB；场景与 fork 串行。监测整个进程组，启动前可用内存不足 2 GiB 不运行；运行中连续两次越过可用内存 2 GiB 下限或 RSS 12 GiB 上限时终止。OOM、fork 失败或资源保护触发后停止后续场景，并保留失败与未完成记录。

## 结果表达

分别报告构建、小数据测试、真实全量正确性、短预检、正式性能结果、Git/PR/CI 状态。原始结果保存在忽略的 benchmark-results 目录，仓库提交小型摘要及分析。样本量不足时不能宣称尾延迟稳定；未完成的场景不补写成绩。没有 Rust/JNI 数据时不输出跨候选加速比或采用结论。WSL2 结果只代表本地可行性证据。
